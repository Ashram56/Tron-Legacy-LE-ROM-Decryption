# rom_data/settings: pricing, audits, adjustments, service texts

This folder covers Tron Legacy LE v1.74 (trn_174h) and is regenerated by
`python3 rom_data/tools/settings_extract.py`. The script reads the ROM through `rom_data/tools/rom.py`,
`code/tron_game_decompiled_v2.c` and the emulator logs in `emu/`. The emulator harness is
`rom_data/tools/settings_emu.cpp`; build it like the other harnesses and run it as
`PINMAME_NOJIT=1 settings_emu script.txt out.log`.

Every row has a `tag`, which gives the strongest evidence for that row:
- `observed`: seen in the emulator. The matching log is in `emu/`.
- `code`: read from tables or disassembly.
- `inferred`: reasoning only.

Every address is hex. Addresses 0x04xxxxxx are ROM tables, 0x36000-0x3ffff are RAM tables copied from ROM at boot,
and 0x21xxxxx is NVRAM.

## Files
### pricing.json / pricing.csv
- `credit_system`: the struct at 0x040e0bd8:
  - state at NVRAM 0x2111008 = {s32 pos, u8 credits, ~checksum8}
  - pricing pointer table at RAM 0x38078
  - custom record at 0x2110808, custom coin door at 0x2110824, custom ladder at 0x211089c
  - slot counters 2-6
  - adjustments 28 (pricing), 62 (coin delay), 34 (free play) and 33 (credit limit)
  - meter 1, units counter 7, credits counter 1, lockout output 5
- `algorithm`: pseudo-code of coin task 0x4a50, credits_add 0x4890, display 0x4ff4 and the fraction function 0x4d48, with addresses.
- `presets[]` (pricing.csv has one row per preset):
  - `adj_value`: value of adj 28 GAME PRICING. `name` comes from msg 0x299+i.
  - `record`: the 0x18-byte pricing record {coin-door ptr, unit_index, ladder ptr, ladder len, name msg, format msgs}.
  - `coin_door`: a table of 12-byte entries {u32 unit value in 1/100 currency, u8 units per slot[5]}.
  - `unit_value_minor`: the coin unit in 1/100 of the currency.
  - `slotN_units`: units credited per coin on slot N. Slot 1 = LEFT (coin key 3 in PinMAME), 2 = CENTER (key 4), 3 = RIGHT (key 5), 4 = FOURTH (key 6), 5 = FIFTH.
  - `slot_money`: the money value of each slot.
  - `ladder`: credits awarded at each unit position. The position wraps at `ladder_len`.
  - `first_credit` / `awards`: money per credit step, derived from the ladder.
  - `service_summary`: the text that the ROM's own summary function 0xac18 produced (observed for all 64 presets in emu/t7.log).
  - `factory_default_for`: the countries whose factory default selects this preset.
- `verification_log`: the emulator lines from emu/t3.log. They show:
  - USA 10 (index 62): 3 quarters = 1 credit, and $1 shows "CREDITS 2 1/2".
  - GERMANY 2: 1 EUR = 2 credits, 2 EUR = +5.
  - EURO 3: 50c = 1 credit, 1 EUR = 3.
  - FREE PLAY display, the CREDIT LIMIT cap and COIN INPUT DELAY OFF.

### audits.csv (150 rows)
- `menu` / `menu_label`: the number shown in the menu. It is the position in that sub-list:
  - EARNINGS AUDIT #1-13 = audits 1-13
  - STANDARD AUDIT #1-59 = audits 14-72
  - FEATURE AUDIT #1-78 = audits 73-150
- `table_entry`: the 16-byte record {fn, name ptr, counter<<16 | display type, flags}. Flags bit 0 adds the LIFETIME line (msg 0x268, selector 0x90).
- `counter` / `counter_nvram` / `counter_flags`: the counter-table entry when the audit is a plain counter.
- `display_type`: 1 "%d", 2 "%d%%", 3 m:ss, 4 money (0x2e62c, which uses the CURRENT pricing unit value), 5 score, 6 "x% OF GAMES".
- `computed_fn` / `formula`: present when the audit is computed. Division by zero gives `div_by_zero`.
- `incremented_by`: audit_add 0x178c call sites.
- `observed_zero` / `observed_poked`: the formatter output with all counters at 0 and after poking test values (emu/t4.log). The formula rows were checked this way:
  - 11 TOTAL EARNINGS = counter 7 x unit value: 13 units gives "USD 3.25".
  - 13 SOFTWARE METER: fn 0x32b24 always returns 0.
  - 72 RECENT REPLAY PERCENT: fn 0x2e3e4 always returns 0.

### adjustments.csv (88 rows) and adjustment_readers.csv
- `adjustments.csv` columns:
  - `menu_label`: STANDARD ADJUSTMENT #n follows the order list at 0x39558. FEATURE ADJUSTMENT #n = adj 64+n.
  - `nvram`: the value's NVRAM address.
  - `default`: the table default. `factory_default_usa`: the value after INSTALL FACTORY (0x1278) with country U.S.A.
  - `min` / `max` / `step`: limits from the table. `wraps`: no if record byte +0x1e has bit 0 set.
  - `display_type` / `formatter` / `labels`: the value labels, either from a msg list or by running the formatter function in the emulator (emu/t8.log).
  - `visible_if`: the rule in visibility function 0x34124.
  - `country_overrides`: values set per country by the OS, game and CEC lists.
  - `readers`: adj_get 0xe90 call sites.
- `adjustment_readers.csv` has one row per accessor site:
  - all 109 `adj_get 0xe90` call sites
  - struct-based reads, such as credit-system fields
  - generic code, such as adj_set 0xf8c, reset 0x1080, menu and formatters
  - `observed_calls`: the hit count from emu/t2_adj_get_counts.txt and emu/t3.log
- No code reads the adjustment NVRAM directly. Every read goes through 0xe90.
- **Adj 25 FREE GAME LIMIT has no game-logic reader.** It is written only by the menu, INSTALL FACTORY, the ADD-A-BALL / NOVELTY install lists (value 0) and the CHUCK-E-CHEESE country list (value 1). Its formatter is 0x2e06c.
  - Observed: with adj 25 = 0, replay award 0x22d2c still added a credit. In v1.74 the setting has no effect.
- The other adjustments with no adj_get site are 1, 5, 6, 8, 9, 37, 43, 45, 47 and 87 (marked `none` in `readers`).

### presets.csv
- `kind=install`: INSTALL menu items 71..:
  - 0x1041a10 applies the OS list at `list_address` with adj_apply_list 0x10e8, then the game list.
  - 0x1118 checks whether the preset is INSTALLED.
  - The difficulty presets (EXTRA EASY .. EXTRA HARD) are empty in both lists.
  - The game lists at 0x36f7c.. are all empty.
- `kind=country`: the factory overrides per country:
  - The OS list is at country record +4, the game list at +8, and the CEC/redemption defaults at +0xc/+0x10.
  - Precedence in 0xf28 -> 0x5f2c: country game list > list 0x39480 > country OS list > table default.

### service_texts.csv
There is one row per (msg, drawing site) in the service menus.
- `role`:
  - menu item name: drawn by renderer 0x1037588 at y=0x1e.
  - text_draw_msg / text_draw_msg_fit / text_printf_msg / msg_get: a direct call inside a screen function.
  - adjustment value label.
  - pricing preset name.
  - country name.
  - install screen text.
  - `dynamic: <expr>`: the id is computed at run time. `msg` stays empty unless it was resolved.
- `screen_fn` / `drawn_by`: the function that draws the text. Screens were found by a search 3 calls deep from each menu item's action and screen functions in the decompile.
- **msg 0x113 "LAST SW. #%d" and 0x114 "LAST SW. D-%d"**: SWITCH TEST (item 21, screen 0x1044bfc) draws one of them at y=0x15 under the switch name (or under "NONE", msg 0x115). The draw is text_printf_msg 0x28d5c at 0x1045094 / 0x104512c.
  - 0x113 is used when 0xdec0(sw) is non-zero (a matrix switch, number printed as is).
  - 0x114 is used for a dedicated switch (number - 0x80).

### menus_runtime.json
This file lists the item ids of each menu (1..17) as built at run time by 0xf754 with the factory settings (observed). The game inserts its own items through event 0x5d.

### emu/
- t*.txt are the harness scripts and t*.log their filtered output. Per-second audit_add lines for counters 59-64 were removed.
- t1 dumps runtime RAM.
- t2 / t3 cover adj_get counts and coin tests.
- t4 covers audit formulas.
- t6 covers country factory defaults.
- t7 covers the pricing summaries.
- t8 covers the formatter labels.

## Open items
- **PinMAME DIP country**: `PinmameSetDIP` had no effect in the harness (dip0 stayed 0x80). Other countries were emulated by writing NVRAM 0x21100d8 (country) and 0x21100d9, rewriting the checksum (0x27a0) and calling 0x1278.
  - Germany was checked this way: pricing 24, language 1, adj 35 = 1.
  - The CEC list was checked for adjustments 28, 25 and 13.
  - The rest of the country rows are `code`.
- **Unresolved dynamic text ids**: rows with `dynamic: ...` and an empty `msg` are text drawn from a table or argument, such as test names, error-log entries and the ticket test. They were not traced one by one.
- **CUSTOM pricing** (adj 28 = 64): the row shows the factory-empty NVRAM record. Its 0xac18 summary was not captured.
- **Adjustments with no reader** (1, 5, 6, 8, 9, 37, 43, 45, 47, 87): the absence is `code` (no adj_get site), but some may be read by OS code through a struct or a computed id. 9/87 MUSIC VOLUME is likely applied by the sound task through another path; this is `inferred`.
- **DISPLAY HELP SCREEN**: action 0x103db6c is an empty stub, so no help texts are drawn.

## Contradictions with existing docs
- `mpf_package/config/settings.yaml:2397` and `mpf_package/service_menu.md:149` give adj 10 PLAYER LANGUAGE SELECT a default of 0 (NO). The USA OS list 0x38fd4 sets it to 1, and the value observed after INSTALL FACTORY with U.S.A. is YES.
- `mpf_package/service_menu.md` (tables at lines 104 and 216) numbers adjustments 1-88 and audits 1-150 by table id. The machine shows other numbers:
  - Audits use the position within each list: STANDARD AUDIT #1 = audit 14, FEATURE AUDIT #1 = audit 73.
  - Standard adjustments follow the order list 0x39558: adj 1 COIL PULSE POWER is STANDARD ADJUSTMENT #43. See `menu_label`.
- `mpf_package/service_menu.md:40` puts GAME-SPECIFIC TESTS last in the diagnostics menu (and line 100 says its position was inferred). At run time (0xf754, factory) the order is SWITCH, COIL, FLASH LAMPS, LAMP, GAME-SPECIFIC TESTS, BALL TROUGH, ... DOT MATRIX, RETURN, EXIT, HELP. Item 14 DISPLAY SOFTWARE ERRORS is hidden at factory.
- `mpf_package/service_menu.md:86,91` marks TOURNAMENT and REDEMPTION as conditional. With the factory settings both are visible: MAIN = DIAG, AUDITS, ADJ, UTIL, TOURNAMENT, REDEMPTION, EXIT (observed).
- `AGENTS.md:236` says install presets sit "near the menu tables". The OS lists are in the RAM-init area 0x394xx and the game lists at 0x36f7c..; both are referenced from install functions 0x1041d38...
