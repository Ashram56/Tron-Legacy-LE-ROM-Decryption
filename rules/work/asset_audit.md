# Audit of tron/mpf_package (Tron Legacy LE v1.74)

Audited 2026-10-02 against `trn_174h.bin`, the decompile `tron/code/tron_game_decompiled.c`, and the ROM tables.
Nothing under `mpf_package/` was changed. Every finding below comes from a ROM read, a decompile line or a file
check. Anything not checked that way is marked **unverified**.

Address conventions: `0x01xxxxxx` is game code, `0x04xxxxxx` is data (file offset = addr - 0x04000000).
"Tick" = one `task_sleep(1)`, about 16.3 ms (from the package's own timings, cross-checked below).

## Verified correct

- **Deff table**: all 145 `rom_function` and `priority` values in `event_map.csv` match the ROM table at 0x040e1350 (prio = high half of word 2). `background_loop=yes` matches exactly the 15 entries with flag low bits = 1.
- **Deff text**: for the other ~140 deffs, `rom_text` matches the message ids each function draws (table 0x040eeb7c, English string). Exceptions are in C1.
- **started_by_code**: every non-empty entry matches the direct `deff_start` callers in the decompile. Many entries are blank where the caller goes through `FUN_0100fbb0` (e.g. 46, 52, 54, 56, 64, 71, 76, 85, 103, 105, 132, 133, 139); filling them would help.
- **Switch numbers and names** in `switches.yaml` match the descriptor table at 0x040f3574 (name pointer at +8; index i = switch i+1); the NOT USED switches are correctly left out.
- **Coil numbers and names** (1–35) match the coil name table at 0x040e0c00. **Lamp numbers and names** (1–66) match 0x040e2bf4.
- **Sound pools**: each of the 254 `call_XXX` pools holds the same sample list, in the same order, as the ROM call table at 0x040f16b4 (+8 → zero-terminated u16 list). Call 0x12a has 631 samples and matches too. `sound_calls.csv` matches as well. `random_force_all` is a fair stand-in for `snd_resolve_call` (0x2c744): random start index, skipping recently played samples.
- **Sample rates and durations**: all 1,090 WAVs are mono 16-bit with the rate given in `samples_index.csv` (804 speech at 12 kHz, 53 speech at 24 kHz, 212 sfx and 21 music at 24 kHz). Each duration equals the ROM length field/4000 s (4 multi-segment sfx are within 10%). Package WAVs are identical in size to `tron/samples`.
- **Timing spot checks** (tick about 16.3 ms):
  - deff 104: 63 frames (images 0x7f2–0x830 = 2034–2096, as in `images_used`) x 3 ticks = 49 ms each, then a 10-tick hold (last frame 221 ms) ✓.
  - deff 106: 20 x 6 ticks, then speech 0x04f; timing says 0x04f at 1952 ms ✓.
  - deff 108 captured clip (case 3: 0xa5d+, 2 ticks) at 32–33 ms per frame ✓.
  - deff 105 scroll: 3 ticks per step, 49 ms ✓; sound 0x0e3 at 883 ms right after the scroll ✓.
  - deff 10/15/17: 13 x 15 ticks = 3184 ms ✓.
- **Other checks**: deff 108 tube show `leff_059` matches `FUN_0101b824(0x3b)` in code ✓. Deff 100 is started from the sw12 ZEN handler ✓. Deffs 101/102 skill-shot starters are on the sw37/sw34 paths ✓.
- No duplicate keys in any other YAML (553 files checked, incl. `shows/` and `io/mpf/`).
